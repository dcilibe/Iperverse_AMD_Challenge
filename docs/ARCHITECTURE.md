# Architecture — AMD-powered evolving game

## Purpose
A standalone original browser-based 2D top-down arena. Adaptive NPC behavior and a procedural level directive are generated by an AI World Director. The 2D client runs locally in the browser; inference can run remotely using an AMD-hosted model.

## Components
- Browser Canvas2D at public/: input, tactical NPC movement, collision, rendering and responsive HUD.
- Game rules at public/game-core.js: seed-based generation, NPC tactical styles, finite limits.
- Node HTTP backend at server/: same-origin static serving and POST /api/world/evolve.
- Provider adapter at server/provider.js: optional OpenAI-compatible model endpoint. Until validated against the actual AMD TokenFactory account, support is CONDITIONAL, not certified.
- Contract at server/world.js: sanitizes event telemetry and validates model-produced world directives.
- Simulator: deterministic local result, explicitly labelled `simulator` in responses/UI for offline development.

## API
GET /api/health -> {status,provider,configured}
POST /api/world/evolve accepts bounded {seed,level,kills,hp,elapsed,style}; returns {source,world}.
World fields: {seed,biome,strategy,density,obstacleCount,narrative}. All are allowlisted/bounded. Neither model output nor client may dictate code paths, remote asset URLs or arbitrary game resources.

## Real AMD deployment checklist
1. Confirm an approved AMD inference API, exact model ID and its endpoint compatibility. An AMD membership does not imply dedicated free GPU hosting.
2. Copy .env.example parameters into your environment (never commit secrets). Provide AMD_API_KEY, AMD_BASE_URL, AMD_MODEL.
3. Start server and call /api/health. It says `amd-configured` only when required values exist.
4. Trigger a new stage in the game. UI and response must show `amd`, not `simulator`. A failed AMD request surfaces an error; no fake successful AI fallback.
5. Capture model, provider, real latency, generated JSON, validation outcomes and screenshot as submission evidence.
6. For a self-hosted dedicated GPU, serve an OpenAI-compatible /v1 endpoint with a supported inference engine, ROCm and model license. This is optional and may incur billing.

## Security boundaries
- API key only in the server process; never exposed in JS bundle, URLs or logs.
- Rate limit and body limit per client; model request has a timeout and capped output tokens.
- Same-origin API and static allowlist to avoid path traversal.
- User telemetry is numeric/allowlisted, no personal data.
- Local simulator never masquerades as AMD; fail visibly when AMD errors.
- Do not deploy public backend without edge TLS, provider budget caps and abuse controls.

## VR later
WebXR requires an independent 3D renderer and XR input surfaces; do not promise a 2D Canvas port is VR-ready. Keep domain rules and model contract reusable.
